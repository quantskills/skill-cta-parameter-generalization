# 成交约束情景回放

原有分析比较参数的迁移表现。这个独立工具回答另一个问题：给定资金、手数、涨跌停和容量假设，账本会怎样变化。两套结果不要混用。

## 先运行示例

```bash
python scripts/execution_constraints.py --input examples/execution-constraints.json --output outputs/constraints-demo
```

打开输出目录的 `使用结果.md`。示例是人为构造的：250 元资金不能买入目标的 5 手，只能开 2 手；第二天跌停无法卖出，持仓继续保留，权益变为 -154 元并报警。这不是某个真实合约的历史表现。

## 替换自己的输入

输入为 JSON。顶层填写初始资金 `initial_capital`、每手单边手续费 `fee_per_lot`、不利滑点价格 `slippage` 和逐行 `rows`。

每行需给出合约、目标手数、开收盘价、合约乘数、保证金比例、上下限价格、可成交手数容量，以及带时区的决策、信号产生、开盘、收盘时间。例子包含完整字段。目标手数正数为多、负数为空，小数向零取整。信号必须先于或等于决策时间，决策必须早于开盘。每行时间必须递增且不能重叠。

`rule_available_at` 和 `capacity_available_at` 代表规则与容量假设何时已知。填写晚于决策时间会被拒绝；没有证明可以填 null，但结果明确标为假设。输入了时间也不等于供应商或交易所已认证它。

不要把当天收盘后才知道的成交量当成开盘可成交容量。容量应来自事前限定的保守情景或有时间证明的记录。每日规则需自行准备，工具不自动补全历史保证金或涨跌停。

## 如何读账本

- 先尝试平仓，再尝试开仓；容量是本行买卖合计上限。
- 买入触及涨停、卖出触及跌停，或滑点后的成交价超限时，本行委托不成交。即使实际市场可能有少量成交，这里也保守拒绝。
- 手续费每次成交都收；权益按收盘价计量，等于初始资金加累计已实现和未实现盈亏，再减手续费。
- 保证金缺口不会被隐藏，也不会虚构一次强平。开盘已有缺口时不再开新仓；可以尝试减仓。期末未平仓仍列在结果中。

## 当前边界

仅支持一个合约的一段连续记录，不支持换月。价格要求为正数，因此不能用于负价格期货情景。固定单边手续费不代表真实平今、平昨费率。没有挂单队列、逐笔撮合、强平规则、资金利息或多合约组合保证金。收盘价是盯市标记，不声称是交易所结算价。输出始终 `executable=false`，不连接账户、不发送订单。

这个工具用于暴露不合理的成交假设；测试通过不证明原研究能实盘执行，更不证明参数优化盈利。
